The idea

Old stationery, translated for machines.

For centuries, letterhead, a signature and a seal showed at a glance what a paper was and who it was from. Typographics Art brings that to the AI age, in three layers.

The document

Markdown plus a few required metadata fields, with stable sections, hashes and a version chain. On its own, already a useful “llms.txt with structure.”

The provenance

Keys on domains, signatures, a visible seal, a verify tool — the piece missing in the world today. Signatures exist for software and for photos, but not yet a widespread, readable one for texts addressed to AIs. Keys and signatures are anchored in public transparency logs, optionally in Bitcoin via OpenTimestamps — the anchors are pluggable and open to the community, not tied to one chain. Shipping in this release.

The picture

No longer the core, but the reason people understand the format without reading the spec: a seal on an envelope needs no explanation. The picture turns a crypto protocol into an object you recognise, show and hang up.

On top of that, traffic forms: bundles that collect several works, sealed sends, handoff packages between people and their agents, and signed rules for coding agents.

The picture layer, up close: the words are never thrown away.

What it is not

Not a replacement for PDF, and not a security system against a malicious author — a signature proves who signed, not that they are honest. How it works

Four steps from text and photo to an artwork that is also a document.

Measure

Every character is measured in ten weights of one variable font, Roboto Flex: how wide it is, how much ink it covers.

Map

The photo becomes an ink demand per area: dark areas want heavy letters, light areas thin ones.

Set

Line by line, each letter gets the weight, width and size that match its area. The leftover error is passed on, so tones average out.

Verify

The finished artwork is read back like a machine would and compared with the source. Only then is it done.

The headline use case

Know where a text is from — and that it hasn't changed.

AI agents now read text all day — repositories, policies, instructions, emails — and act on it. But a block of text carries no origin: an agent cannot tell your real AGENTS.md from one swapped in by a man-in-the-middle, your refund policy from a tampered copy, a genuine statement from a forged one. That gap is the opening for phishing, prompt injection and poisoned instructions.

Typographics Art closes it with the piece missing in the world today: a readable, verifiable signature for AI-facing text. A Typogram can be signed by its issuer — a domain you recognise — and anyone, a person or an agent, can check who published it and that not one character has changed since. It is shipping in this release.

Sign

An issuer is a domain — say your-company.com — with an Ed25519 key. It signs the work's identity hash: the SHA-256 of its canonical text, so the signature is independent of fonts, rendering and file format. The signature, the issuer, a key id and a date are written into the work's data layer; the picture and the text are left untouched.

Publish the key

The issuer's public key lives at https://your-company.com/.well-known/tgart-keys.json, as a self-contained signed key statement — the key signs its own statement. On rotation the previous key also signs the new one, so the chain stays provable even for a work found far from the domain.

Anchor

The key is also anchored in a public transparency log, and optionally in Bitcoin via OpenTimestamps, so it cannot silently change or disappear. The anchors are pluggable and open, not tied to one chain.

Verify

Anyone — a person or an agent — recomputes the hash from the work, fetches the issuer's public key from that .well-known URL, and checks the signature. The result is one of three: verified (from this issuer, not one character changed), unsigned, or tampered.

What it unlocks

Rules your coding agent can trust

A coding agent clones acme.dev's repository and reads its AGENTS.md as a signed Typogram. Before it follows a single rule, it recomputes the hash, fetches Acme's key from acme.dev/.well-known/tgart-keys.json and confirms the rules are really Acme's and unchanged — not injected by a poisoned mirror or a man-in-the-middle.

A policy an AI support agent can act on

An AI support agent is about to approve a refund. First it verifies the refund policy is really from your-company.com, signed and character-for-character unchanged, before it quotes a single term — so a tampered clause can't talk it into the wrong decision.

What it proves, and what it does not

A signature proves who signed and that the text is unchanged — not that the signer is honest. And it is a possibility, not a guarantee: whether an agent actually runs the check depends on verify tools landing where models run, and on issuers whose seal people recognise.

Hidden messages

A message only the key holder can read. The work stays exactly as it is.

Write a secret, pick a work, and get a key. The work keeps only its public text, nothing invisible is added. The key records where the letters of your secret stand in that text, chosen at random. With the key and the right work, the secret comes back.

Write

Type the message to hide, in the generator or on the command line.

Key

For every character, one random occurrence in the public text is chosen. Two keys for the same message look completely different.

Share

The work goes public, the key goes only to the person who should read the message. Keep it like a password.

Read

Key plus work gives the message back. With any other work the key's fingerprint does not match.

Data in a work

A spreadsheet inside a picture, read back by a machine. Sealed, if it must stay private.

An Excel, CSV, JSON or Markdown file becomes a block of plain text that goes through a work unchanged, survives PDF extraction and decodes back to the data with a checksum. The same data can be sealed with a key, so the work carries only its public text.

Encode

Attach an .xlsx, .csv, .json, .md or similar file in the generator. TGD 1.0 turns it into whitespace-proof text with its own checksum, in your browser; nothing is uploaded.

Carry

The block is ordinary visible text in the work: a PDF, SVG or HTML holds it, and the work page shows the table again, checksum verified, with downloads as .xlsx, .csv, .json.

Seal

AES-256-GCM with a key that fits exactly one work. The work stays untouched; you get a key and a sealed record. A wrong key or a changed byte is detected on the work page.

Keys

One seed backup, many records: a master key and one key per record, keys that can be split among several hands, a passkey as a factor. A password is never the only secret.

Is it secure?

The cipher is sound; the code around it is tested but not independently audited, and all the security is the secrecy of the key. “Cannot be read without the key, as far as today's cryptography is known” is true; “nobody can ever get at it” is not: a lost key loses the data, a compromised device defeats everything, and a password alone never protects anything public.

Status: in the browser you can attach a file, write it into a work or seal it, and read both back on the work page (no server, no third party). Still command line only: passwords, compact book keys, inline keys and a sealed block inside a work.

FAQ

Questions

Is the text really complete?

Yes. Every artwork is read back and compared with its source; the reports state the method and the result. Whitespace is normalised to single spaces, and declared filler (Lorem ipsum, for finer pictures) is counted separately.

Can an AI read it from a photo or screenshot?

Partly. Classic OCR reads about 99 % at the highest legibility setting and less at artistic settings; a vision model read every word in our samples. For a perfect result, share the HTML, SVG or PDF: the text is in the file.

Is it a calligram?

No. Calligrams arrange text along a shape, usually by hand. Typographics Art keeps a normal reading layout and creates the picture only through the typography of each letter, computed from any photo.

Does it cost anything? Can I use it commercially?

It is free and MIT licensed, also for commercial use. Mind the rights to the texts and photos you use.

Is my text uploaded somewhere?

No. The web app runs entirely in your browser.

Has this been done before?

Making a picture from text is old: micrography wrote scripture into images by hand from about the 9th century, and ASCII art turns images into glyphs by machine. What is new is the combination — a given text set once in reading order, the picture made only from per-letter typography, and the result verified to read back as the source. See prior-art.md.
